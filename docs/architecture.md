# 技术架构详细文档

## 一、系统定位

不追求"训练模型"，而是构建一个**LLM驱动的决策系统**。

- 无需历史数据：靠LLM推理 + 运筹优化求解
- 核心价值：异常检测、推理决策、全局优化
- 部署轻量化：4GB GPU + 32GB RAM可运行

## 二、为什么这样设计

### 2.1 为什么不纯用RAG
RAG只能检索，不能求解。物流调度的核心是**约束求解**（NP-hard VRP问题），这需要专业的求解器而不是检索。

### 2.2 为什么不训练模型
- 没有现成数据
- 训练周期长，效果不确定
- LLM的推理能力已经足够应对异常场景

### 2.3 为什么用混合架构
- **LLM**：异常推理、决策建议（擅长泛化、推理）
- **OR-Tools**：全局最优求解（擅长约束优化）
- **RAG**：经验参考（擅长历史相似case）
- **量化模型**：实时打分（本地部署、低延迟）

## 三、模块设计

### 3.1 仿真环境 (simulation/)

**目的：** 生成模拟物流数据，用于测试和开发

**生成内容：**
- 车辆数据：ID、容量、当前位置、状态
- 订单数据：ID、重量、体积、提货点、配送点、时间窗
- 路况数据：路段、拥堵系数、预计时间
- 异常事件：事故、订单取消、交通管制

**输入输出：**
```python
# 输入：场景配置（车辆数、订单数、区域大小）
# 输出：SimulationData，包含vehicles, orders, road_network, events
```

### 3.2 优化求解器 (optimizer/)

**目的：** 用OR-Tools做全局最优调度

**核心算法：**
- 车辆路径问题（VRP）— 基础求解
- 带时间窗的VRP（VRPTW）— 考虑时间约束
- 带容量约束的VRP — 考虑车辆负载
- 异常重规划 — 突发情况下的快速重求解

**接口设计：**
```python
class VRPSolver:
    def solve(self, vehicles, orders, constraints) -> RoutePlan:
        """返回最优路径规划"""
    
    def reroute(self, original_plan, event) -> RoutePlan:
        """异常事件后的重规划"""
```

### 3.3 LLM Agent (agent/)

**目的：** 异常检测 + 决策推理

**能力：**
1. **异常检测** — 输入事件，输出是否异常 + 严重程度
2. **决策建议** — 输入异常场景，输出处理建议
3. **方案评估** — 对OR-Tools的求解结果进行评估和解释

**Prompt设计原则：**
- Few-shot注入领域知识
- CoT思维链提升推理质量
- 输出结构化（JSON格式便于解析）

### 3.4 RAG增强层 (rag/)

**目的：** 提供历史经验参考

**数据来源：**
- 历史调度case：成功/失败案例归档
- 规则知识库：公司政策、优先级规则
- 行业最佳实践：公开的物流优化案例

**检索策略：**
- 向量相似度检索（语义匹配）
- 关键词过滤（硬约束）
- 重排序（Rerank）

## 五、硬件适配

### 5.1 RTX 3050 (4GB) 能跑什么

| 模型 | 量化 | 显存占用 | 适用场景 |
|------|------|---------|---------|
| Qwen2-7B | 4-bit | ~4GB | 实时推理、打分 |
| Phi-3-mini | 4-bit | ~3GB | 轻量推理 |
| Llama-3-8B | 4-bit | ~5GB (超限) | 不推荐 |

### 5.2 加速策略

- **GPU推理**：量化模型用llama.cpp + CUDA加速
- **CPU求解**：OR-Tools单线程够用，求解VRP很快
- **API备用**：复杂推理可调用Claude API

## 六、技术选型理由

| 组件 | 选型 | 替代方案 | 理由 |
|------|------|---------|------|
| 求解器 | OR-Tools | Gurobi, CPLEX | 开源、免费、支持VRP |
| Agent框架 | LangChain | LlamaIndex, 自研 | 生态成熟、集成度高 |
| 量化推理 | llama.cpp | vLLM, ollama | 轻量、4GB兼容好 |
| 向量DB | Milvus | PgVector, Chroma | 支持大规模检索 |

## 七、已否决方案

1. ❌ **纯RAG系统** — 不能做约束求解
2. ❌ **训练专用模型** — 无数据、周期长
3. ❌ **Llama-3-8B量化** — 4GB跑不动8B
4. ❌ **规则引擎单独决策** — 异常场景泛化能力差
